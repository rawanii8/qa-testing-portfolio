# [Web] Internal debug information (phone number, region, unit config) exposed directly in production UI on Pricing page (post-login)

**Severity:** High
**Priority:** High

## Description
After logging in, navigating to the Pricing page ([the agricultural management platform staging URL] ) displays a debug/diagnostic line rendered directly in the page: "Debug: Phone: [REDACTED_PHONE_NUMBER] | Region: MENA | Unit: faddan". This appears to be internal development/debugging output mistakenly left active in production. The exposed phone number corresponds to the logged-in user's own account data, confirming this debug line pulls and displays real authenticated user data — making this both a debug-code leak and a personal data exposure issue, since any logged-in user can see their own (and potentially, depending on implementation, other users') phone number rendered in plain text on a public-facing page.

## Steps to Reproduce
1. Navigate to: [the agricultural management platform staging URL]  and log in with a valid account
2. After successful login, navigate to: [the agricultural management platform staging URL]
3. Observe the subtitle area directly below the page heading "اختر خطتك"
4. Look at the text below "Middle East & North Africa / عرض الخطط لـ"

## Actual Result
A visible debug line is rendered: "Debug: Phone: [REDACTED_PHONE_NUMBER] | Region: MENA | Unit: faddan", exposing the logged-in user's phone number and internal configuration values directly in the production UI.

## Expected Result
No debug/diagnostic output should ever be rendered in the production UI, whether for logged-in or anonymous users. This line should be removed entirely, and any debug logging should be restricted to server-side logs or development/staging environments only, gated behind an environment flag (e.g., {{if (process.env.NODE_ENV !== 'production')}}).

## Environment
* URL: [the agricultural management platform staging URL]  (post-login)
* Browser: Microsoft Edge
* Language: Arabic (RTL)
* Section: Pricing page header/subtitle area
* Precondition: User must be logged in
