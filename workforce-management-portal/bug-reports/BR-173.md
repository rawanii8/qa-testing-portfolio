# Employee filter on Screenshots page fails to display isolated user data and loads screenshots from other employees

**Severity:** High
**Priority:** High
**Status:** new

## Description
In the Screenshots (لقطات الشاشة) module of the workforce management platform, the employee filtering functionality does not correctly restrict results to the selected employee.

When an administrator selects a specific employee from the filter pills, the system continues to display screenshots belonging to multiple employees. As additional records are loaded through the "تحميل المزيد" (Load More) functionality, screenshots from other employees are appended to the same results list instead of maintaining the selected employee filter.

This behavior defeats the purpose of the employee filter, makes screenshot reviews inefficient, and can cause confusion when monitoring employee activity.

## Steps to Reproduce
1. Log in to the internal web portal as an administrator.
2. Navigate to Monitoring (المراقبة) → Screenshots (لقطات الشاشة).
3. Select a specific employee from the employee filter pills (e.g., Mohammed Elkasry or Aya Hassan).
4. Review the screenshots displayed in the gallery.
5. Scroll down and click "تحميل المزيد" (Load More).
6. Continue reviewing the loaded screenshots.

## Actual Result
- Screenshots from multiple employees are displayed despite selecting a specific employee.
- Clicking "تحميل المزيد" appends screenshots belonging to other employees.
- Results are not properly restricted to the selected employee.
- Managers must scroll through unrelated screenshots to find the desired employee's records.
- Filtered results behave like a global screenshot feed rather than a user-specific view.

## Expected Result
- Selecting an employee filter should display only screenshots belonging to the selected employee.
- The screenshot gallery should refresh and clear previous results when the filter changes.
- The Load More functionality should continue loading screenshots exclusively for the selected employee.
- No screenshots from other employees should appear while a user-specific filter is active.
- Backend requests should respect the selected employee identifier and return only matching records.

## Environment
- Browser: Chrome (latest)
- OS: Windows 11
- Device: Desktop
- URL: the internal web portal/admin/monitoring/screenshots
