# Message input remains disabled when starting a new conversation via Search & Add flow

**Severity:** High
**Priority:** High
**Status:** new

## Description
In the Communication module, users are unable to start a new conversation when initiating chat through the Search & Add workflow.

When selecting a user who does not have an existing conversation history, the system opens the chat window but fails to properly initialize the new conversation state. As a result, the message input field remains disabled and users cannot send messages.

This issue appears to affect only newly initiated conversations through the search flow, while existing conversations continue to function normally.

## Steps to Reproduce
1. Log in to the workforce management platform portal
2. Navigate to Communication
3. Click the Search or Direct Message option
4. Search for a user with no existing chat history
5. Select the user and add/open the conversation
6. Observe the chat input field

## Actual Result
- Chat window opens for the selected user
- Message input field remains disabled/inactive
- User cannot type or send a message
- New conversation is not properly initialized

## Expected Result
- Selecting a new user via Search & Add should initialize a new conversation successfully
- Message input field should be enabled immediately
- User should be able to send the first message without issues

## Environment
Browser: Chrome
OS: Windows 11
Device: Desktop
